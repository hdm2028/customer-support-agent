## 测试结果与修复

原有 10 项实际 MySQL 测试全部通过：[首次运行](refund_mysql_dedicated.txt)。包括首次 50 次线程并发创建、消息写入失败回滚、消费中订单/ack 失败回滚、租约恢复、旧消费者隔离、重试死信及历史缺事件修复。

新增 4 个独立进程测试，各进程独立内存缓存/锁，竞争同一新订单，随后并发领取同一队列，再投递同一消息。暴露两处问题并保留失败记录：

|问题|实际证据|修改|
|---|---|---|
|唯一键竞争后的幂等返回被外层覆盖为首次创建|退款 ID 只有一个，但四个结果都 idempotent_replay=false；[失败记录](refund_mysql_processes.txt)|refund_apply 保留创建函数返回的幂等标记，只给真实首次创建补充创建者信息|
|同一已完成消息再次进入处理逻辑会重复写通知|核心业务仅一次，但通知四条；[失败记录](refund_mysql_processes_fixed.txt)|持有消息行锁时识别 done，直接返回重复已忽略，不再次执行通知或覆盖原 ack|

[修复后 MySQL 结果](refund_mysql_processes_verified.txt)：**11 passed，6.90 秒**。跨进程断言：一条退款、一条事件、一个真实创建者、只领取一次、核心业务一次、通知一条、消息 done。该结论针对同一 message_id 的重复投递；未声称所有不同事件的通知已全局去重。

[全量单元/集成测试](tests_mysql_followup.txt)：**140 passed、15 subtests passed、1 skipped**，3 条既有框架弃用提醒。此处跳过的是专用 MySQL 多进程项；它已在上面的 MySQL 专项中实际通过。原 RAG/整链路实验产物、评分规则和数据未改动，未运行 validation/final_test。
