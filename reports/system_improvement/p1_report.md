## RAG 桥接

发现 CustomerAgent 已构建 rerank_query，但政策工具只接收 semantic_query 和 lexical_query。新可选路径通过受控 context 将完整 RetrievalQuery 穿过工具执行线程；参数必须与 context 的语义/词法查询匹配。设置 RAG_EVIDENCE_SELECTION=complementary 时，客服政策调用固定 candidate_k=20、top_k=5，沿用已有选择器。默认仍走原 top_k=2 工具配置，不自动启用实验。

[冻结候选实际运行](policy_evidence_bridge.json)：Dev V2 5/6，必要证据 18/19；V1 Dev 17/20。选出的 chunk ID 与 r13 保存结果逐案完全一致，两套数据的所有最终证据正文都进入模型 evidence context。调用了实际 policy_search 和生产 guardrail，再沿用 eval_rag 原评分；expected 仅用于选择后的评分。

此验证覆盖“政策工具→guardrail→模型证据上下文”，不证明最终模型回答完整使用全部证据。默认模板仍只展示前两条，政策摘要有截断和内部实现内容问题，待后续处理。003 的候选缺口没有改动，也未借助 Ground Truth 补充运行时候选。
