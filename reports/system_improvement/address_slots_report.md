# 地址咨询与待补充任务修复

已修复已确认的对话状态错误：语义路由判为地址政策咨询后，关键词预设的 `new_address` 仍使查询被阻断。现在按当前动作类型确定必填项；地址执行仍收集订单号和新地址，咨询可以执行政策查询。没有调整语义模型、评分规则或 RAG 选择器。

等待地址时，疑问消息重新进入路由，不作为地址值保存；显式切换订单替换待补充任务。补地址中的门牌数字不会覆盖已绑定订单；从已有订单咨询转为改址执行时，继承订单并继续询问新地址。这里的疑问识别是有限规则，不能据此宣称所有自然语言切换均已解决。

## 固定条件对照

## 验证、开销与回退

最终隔离完整检查：222 项测试、17 个子测试通过，9 项环境专属测试跳过。新增六项测试覆盖咨询有/无订单、同步/流式、逐轮收集、地址数字、咨询切换、订单切换及咨询转执行。首次检查的两个失败原样保留：一个测试误用了不存在的 memory API；另一个暴露“地址是否”被“地址是”前缀误解析，已修正并回归。

B 没有真实模型调用，四组运行分别为 0.49、3.06、1.40、1.91 秒。这是本地回放耗时，不能与 A 的真实 API 延迟比较或宣称线上提速。本轮没有重新测最终 LLM 生成质量。数据库代码未改，未重复 MySQL/Redis 故障注入；此前真实 MySQL 69 项和 Redis 6 项结果独立保留。
