# P2 运行观测进展（2026-09-08）

本阶段实现就绪探针、管理员聚合指标与告警、命令行检查和实际 LLM usage 采集。部署回滚、备份恢复、自动检查调度和外部通知尚未完成，未部署到现有业务进程。

## 已证实的问题与修改

原 health 固定 success=true，SQLite 不实际访问数据库；现在存活和就绪分开，数据库不可用、Redis 回退、知识索引未就绪或凭据配置缺失返回 503。公开探针不返回数据库路径、异常正文或凭据。

原指标只有逐条 trace，无法直接判断积压或超时；新增窗口内请求分位耗时、工具结果失败分类，以及实时队列积压、租约过期、死信和支付待核实超时告警。统计最多 10000 条 trace，截断会显示并告警；空样本返回 null，不记作良好表现。接口只读且限制管理员，命令行可供调度器采集，尚未自动安装调度器或发消息。

原 Chat 客户端丢弃 usage，界面把估算显示为 Prompt/Completion/Total。现在分别保存实际响应 usage 和估算，界面注明估算及供应商用量覆盖次数。普通/流式客户端均记录调用；缺失 usage 保留未知；流式累计报告只取最后一次。耗时节点的上下文覆盖语义路由和最终回复，流式回复显式关联 trace。
