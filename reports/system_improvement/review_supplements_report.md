# 审核补充材料与工作台版本检查

已补齐去重后补充说明的独立记录：原申请、原风险和原上下文保留，后续内容追加到审核单，记录提交人、时间、提交编号、材料版本及提交时的审核状态。聊天复用待审核单时自动记录本轮说明和实际对话/政策上下文；网页也可按审核单号提交文字补充。

同一身份使用同一编号重试相同内容只保存一次；复用编号提交不同内容返回冲突。用户只能补充自己的审核单，管理员可补充并查看材料；HTTP 入口只接收说明，不允许调用者提供系统采集的上下文。字段和接口说明见 [接入文档](../../docs/payment_integration.md)。

## 审核与锁顺序

审核人员提交批准或拒绝时，携带页面对应的 `supplement_version`。期间若有新材料，服务返回 409 并要求重新查看；决定记录保存所依据的材料版本。这是并发版本检查，不是对人工实际阅读行为的证明。

已完成审核仍可接受后续说明，但标明提交时审核已经完成，不改写原决定、重开审核或触发退款。工作台区分审核中补充与决定作出后补充。当前支持文字及自动保存的对话/政策上下文，文件附件上传尚未实现。

自动补充在审核创建/复用事务释放订单锁后，另行锁审核行追加，不形成订单锁等待审核锁的反向依赖。若批准先完成，后续内容记作批准后的补充，返回当前退款/审核状态。固定 MySQL 时序测试已验证：追加等待审核锁期间，第三个事务仍可取得订单锁；批准和追加随后都完成。补充保存失败不会返回已保存，重试可继续。

完整隔离检查：**256 项测试、42 个子测试通过**，11 项环境专属测试跳过，3 条已有框架弃用警告。专用 MySQL：**96 项测试、21 个子测试通过**，3 项 SQLite 专属测试跳过，耗时 87.68 秒。

网页增加“补充审核材料”表单、补充历史展示和决定提交版本。表单网络重试保留同一提交编号，切换身份清空表单及重试状态；展示通过 textContent 写入文本。实际页面脚本通过 Node 语法检查，原 `reviewSummary` 函数经执行验证，能同时展示原申请、补充文本、政策依据与审核后材料标记。**尚未完成浏览器交互或布局验收**，不将脚本检查等同于浏览器验收。
