# 工具控制逻辑中间件重构

2026-09-11。本轮把 `safe_tool_call`、`execute_tool`、`execute_agent_tool` 接入同一条工具中间件链。沿用现有业务图和业务规则，没有引入新的 Agent 框架，没有切换持久化原型为默认服务。

## 为什么这样拆分

三个入口原先已经共用超时与重试函数，但分别组织结果日志、计时和权限拒绝分支。后续增加控制逻辑时容易只更新其中一个入口。本轮保留成熟的执行策略，统一组织方式：入口只描述调用，中间件负责控制，注册表和业务工具负责执行。

## 执行顺序

```text
三个入口 → ToolCall（每次调用独立创建）
  → 结果日志层：先等待内层结果
    → Agent 权限层：拒绝时直接返回失败，跳过内层
      → 总计时层：覆盖完整尝试和退避
        → 运行策略层：超时、只读重试、异常分类、失败降级
          → 注册表参数校验 → 实际工具
  ← 返回 ToolResult，统一记录结果和失败日志
```

`app/tools/middleware.py` 定义调用上下文和 `compose()`。中间件接收 `(call, call_next)`，调用 `call_next(call)` 继续执行，也可以直接返回结果中止调用。第一个中间件最先进入、最后返回。

`app/tools/executor.py` 中的四个中间件按固定顺序组合，运行策略层继续调用已有 `_execute_callback()`；没有另加一层重试。结果日志层位于最外侧，因此权限拒绝、重试耗尽和成功都经过同一出口，每次调用记录一次最终结果。

## 三个入口保留的边界

| 入口 | Agent 工具权限 | 注册表参数校验 | 整体工具计时 |
|---|---|---|---|
| `execute_agent_tool` | 必须检查，缺失 Agent 身份也拒绝 | 有 | 有 Trace 时记录 |
| `execute_tool` | 保留内部可信调用语义 | 有 | 有 Trace 时记录 |
| `safe_tool_call` | 保留内部回调语义 | 不额外要求注册表 | 保留原来的不记录整体计时行为 |

每次调用独立保存 `runtime_metadata`，避免复用中间件链时串用其他请求的尝试次数和耗时。`enforce_agent_permissions` 明确区分 Agent 入口与内部入口，不用“Agent 名字为空”判断是否可以跳过权限。

参数校验仍由注册表负责，退款事务、幂等、用户订单归属和人工审核规则仍在各自业务层。上下文窗口、回答证据检查、HTTP 身份认证没有在本轮迁入这条工具链；它们不是同一种调用边界。超时线程不会被强制终止的既有语义也没有改变。

## 验证

- 复用 `tests/test_tool_reliability.py` 和 `tests/test_policy_route_alignment.py`。
- 合计 **34 tests passed，21 subtests passed**，详见 [targeted_tests.txt](targeted_tests.txt)。
- 复用上一轮普通 HTTP/SSE/进程重启恢复冒烟，**10/10 通过**，详见 [实际运行产物](../durable_graph_prototype/smoke_20260911_205219_390bf9.json)。

没有运行五层测评，也没有把重构测试通过率表述为业务准确率提升。本轮收益是统一控制入口和减少分支重复；没有声称提高模型效果或降低请求延迟。
